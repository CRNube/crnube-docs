# CRNube Docs — notes for Claude

Commercial-grade WordPress document library for Costa Rican cooperatives. Free core (this plugin, WordPress.org-ready: `readme.txt`, no locked features, no external calls) + **CRNube Docs Pro** add-on (`../crnube-docs-pro`: protected area, reports, license client) + **CRNube Licencias** license server for crnube.com (`../crnube-licenses`). Each is its own repository with its own CLAUDE.md. The user writes in Spanish; reply in Spanish.

## Conventions
- PHP 8.1+ (readonly, enums, `never`), `declare(strict_types=1)`, namespace `CRNube\Docs`, PSR-4 in `src/` loaded by the autoloader in `crnube-docs.php` (no Composer at runtime). 4-space indent.
- Prefix `crnd_` for options, meta (`_crnd_*`), hooks, handles, CSS classes (`.crnd-*`). Text domain `crnube-docs`.
- Source strings in English; every new string must be added to `languages/crnube-docs-es_CR.l10n.php`, then run `composer translations` (fails if one is missing).
- Never register `'intval'` (or other internal functions) as a meta sanitize callback: they receive 4 args. Use closures.
- Templates hold markup only; logic goes in `Frontend\View`. Escape everything on output.
- Run `composer check` (PHPCS security rules + PHPStan level 6) and `npm run lint:js` before finishing; all must pass. After JS changes run `npm run build` — `build/` is committed (sites have no Node).
- JS strings: `__( '…', 'crnube-docs' )` with single quotes (bin/translations.php extracts them by regex) and add them to the es_CR file like PHP ones.
- The user commits and pushes; never run git commit/push.
- Uploads must pass `FileTypes::contentMatches()` (real content vs extension); WordPress itself only inspects images.

## Architecture
- `Domain/`: CPT `crnd_document`, taxonomies `crnd_category` (hierarchical) and `crnd_year` (auto from `_crnd_year` meta or publication year), `DocumentRepository` builds the tree in 2 queries and caches it in a transient keyed by `Support\Cache::version()`.
- `Download/DownloadController`: all file links go through `/doc-download/{id}/{view|download}/`; asks `Access\AccessPolicy` (default `StaffOnlyPolicy`: restricted documents are staff-only; Pro replaces it through the `crnd_access_policy` filter). Never redirects to a file inside a `crnd-private-*` folder.
- `Frontend/`: shortcode `[crnube_docs]` → `Renderer` → `templates/*.php`; vanilla ES module `assets/js/frontend.js` (no jQuery), CSS custom properties.
- `Admin/`: `LibraryPage` owns the "Documents" menu (slug `crnd-library`; the CPT sits under it via `show_in_menu`), classic metaboxes (sites use Classic Editor), list columns/filters, category order + shortcode column, settings page with live preview.
- `Domain/CategoryOrder`: per-category ordering mode (term meta `crnd_sort`: '' inherit | date_desc | date_asc | title_asc | title_desc | manual) and manual order (term meta `crnd_doc_order`, list of IDs). Used by both the public tree and the admin list (`orderby=site`), so admin order = site order.
- `Analytics/`: `Counter` (called by DownloadController; bot/prefetch/30 s dedupe via a short transient keyed by a daily-rotating HMAC visitor key, increments `_crnd_views`/`_crnd_downloads`, fires `crnd_hit` for Pro's history), `UserAgent`. The events table, reports and CSV export are in Pro.
- `Access/`: `DocumentAccess` only *reads* the access settings (doc meta `_crnd_access` inherit/public/private + `_crnd_groups`; term meta `crnd_access`/`crnd_groups`, inherited down the tree; any private category wins); Pro writes them. `StaffOnlyPolicy` is the default policy. `Admin/RestrictedNotice` warns when private data exists and no add-on policy is active. Never widen access silently: without Pro, restricted stays staff-only.
- Extension points for add-ons (documented in README "Para complementos"): settings `crnd_settings_defaults`/`crnd_settings_sanitize` (unknown stored keys survive a save) + `crnd_settings_cards`, library `crnd_library_config`/`crnd_library_enqueue` + JS `crnd.library.documentColumns`/`crnd.library.categoryActions` (`assets/src/library/extensions.js`), REST `crnd_rest_document`/`crnd_rest_category`/`crnd_rest_document_args`/`crnd_rest_document_update`, `crnd_login_url`, `crnd_submenu_order`, `TemplateLoader::include($name, $vars, $dir)`. A `[crnube_docs_portal]` placeholder renders nothing when Pro is off. Add an extension point rather than special-casing Pro in core.
- `Migration/`: `FivoImporter` (detects attachment taxonomies, FIVO first; categories with term meta `_crnd_fivo_term` + option `crnd_fivo_map`; generic levels like "Ver Aquí" folded into the parent; documents point at the same attachment, meta `_crnd_fivo_attachment`, idempotent) and `FivoShortcodes` (scan post_content + `_elementor_data`, replace with backup in `_crnd_fivo_backup`, undo; hand-picked attachments → "Selection: {page}" category under `selecciones-fivo`, term meta `_crnd_fivo_selection`; preview never creates terms). UI: `Admin/MigrationPage` (slug `crnd-import`, vanilla `assets/js/admin-migrate.js`) over `Rest/MigrationController`.
- `Frontend/Block`: dynamic block `crnube/documents` (editor app `assets/src/block`, ServerSideRender) and `Integrations/Elementor` (widgets `crnube-docs-library`, `crnube-docs-portal`; loaded on `elementor/loaded`; PHPStan stub `tests/stubs/elementor.php`). Shortcode, block and widgets all go through `Renderer::render()`.
- `Rest/`: `crnd/v1` documents + categories + migration controllers (Pro adds access and stats) used by the library app (`assets/src/library`, React with `@wordpress/components`, built by `@wordpress/scripts`).
